# Lastro — guia para trabalhar neste repositório

Plataforma de duplicata escritural (antecipação de recebíveis) real: cedente emite,
investidor financia via leilão, sacado confirma/contesta, seguradoras cobrem risco,
admin faz back-office, auditor tem acesso somente-leitura. Monorepo `npm workspaces`.

## Estrutura

- `client/` — React 18 + TS + Vite + React Router + Tailwind (SPA em `/app/*`, páginas
  públicas fora disso).
- `server/` — Express + TS + better-sqlite3 (Postgres é um caminho testado, não o driver
  padrão — ver `docs/postgres-migration.md`), JWT, Zod, WebSocket.
- `e2e/` — Playwright, roda contra um build de produção (`webServer` do
  `e2e/playwright.config.ts`).
- `sdks/node` e `sdks/python` — SDKs oficiais do `/api/v1`.

## A disciplina mais importante: "real-when-configured"

Toda integração externa (rails de pagamento, registradoras, bureaus, OAuth, SISCOAF...)
funciona de verdade quando a credencial correspondente está configurada, e cai para um
modo simulado **claramente rotulado como tal** quando não está — nunca finge sucesso.
Antes de adicionar algo assim, procure se já existe um caso parecido (`lib/registradoras.ts`,
`lib/creditBureau.ts`, `lib/paymentRail.ts` são bons exemplos) e siga o mesmo formato de log
`[nome] X_API_URL/KEY não configurado — ...`. Se não existe uma API pública real pro que você
quer integrar (isso aconteceu com o SISCOAF — ver `lib/regulatoryReports.ts` e
`lib/coafSubmissionReminder.ts`), não invente uma — construa o que for honestamente
automatizável em volta da lacuna real, e documente por que ela existe.

## Padrão de 3 camadas (server)

- `db/*.ts` — SQL cru (`db.prepare().run()/.get()/.all()`), interfaces `*Row` tipadas.
- `lib/*Core.ts` (ou `lib/*.ts`) — regra de negócio, schemas Zod, transformação pra
  view-model (campos `*Fmt` formatados via `fmtBRL()`/`fmtRelative()`).
- `routes/*.ts` — Express Router, `requireAuth`/`requireRole(...)`, `asyncHandler()`,
  `.safeParse()` retornando `400 validation_error`, `recordAuditEvent()` após mutação que
  importa.

## Migrações

Arquivo numerado em `server/src/db/migrations/*.sql` **precisa** de um espelho em
`server/src/db/migrations-postgres/*.sql` com sintaxe Postgres (`GENERATED BY DEFAULT AS
IDENTITY` em vez de `AUTOINCREMENT`, `now()` em vez de `datetime('now')`). SQLite não
altera `CHECK` constraint com `ALTER TABLE` — pra ampliar um `CHECK`, recrie a tabela
(`CREATE TABLE ..._new`, `INSERT INTO ... SELECT` com lista de colunas explícita, `DROP`,
`RENAME`) copiando o schema atual via introspecção (`sqlite_master`), não de memória — ver
`0045_auditor_role.sql` pra um exemplo real. No Postgres o mesmo caso é só
`ALTER TABLE ... DROP/ADD CONSTRAINT ..._check`.

Se a mudança adicionar uma tabela nova, adicione também o `DELETE FROM` correspondente em
`resetDbForTests()` (`server/src/db/index.ts`), em ordem segura de FK, terminando em
`DELETE FROM users;`.

## Papéis e navegação (client)

Toda tab nova no menu lateral precisa de 4 pontas batendo:
1. `ROLE_TABS` em `server/src/data/seed.ts` (quem pode ver).
2. `NAV_ITEMS` em `client/src/data/navConfig.ts` (label/rota/grupo).
3. Rota em `client/src/App.tsx`, sempre `lazy()` + envolta em `<Gate tab="...">`.
4. Se o papel for novo, também `db/types.ts`'s `Role`, `ONBOARDING_STEPS` e
   `DEFAULT_TAB_BY_ROLE`.

`client/src/lib/api.ts` só tem `.get/.post/.put/.del` — não existe `.patch()`.

## Agentes de IA

`lib/agentRuntime.ts` é o loop compartilhado; cada agente é um arquivo em
`lib/agents/*.ts` implementando `AgentDefinition`, registrado em `lib/agents/index.ts`'s
`AGENTS`. Toda tool que escreve algo com consequência real (dinheiro, decisão de
compliance/KYB, registro oficial) precisa de `sensitive: true` — nunca executa sozinha,
sempre passa pela fila de aprovação humana (`routes/agents.ts`).

## Antes de considerar algo pronto

```bash
npm run typecheck   # server + client + sdks/node
npm run test         # server (Vitest+Supertest) + client (Vitest+RTL) + sdks/node
npm run build        # typecheck + build dos dois lados
npm run test:e2e      # Playwright contra build de produção (mais lento, rode por último)
```

Rode o Python SDK separado: `cd sdks/python && python -m pytest -v`.
